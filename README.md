# Exact Contract for Zed

Syntax highlighting for the Contract language of [Exact](https://github.com/expo/exact)
(`.contract` and `.test.contract` files) in the Zed editor.

What it gives you:

- Highlighting for declarations (`component`, `shape`, `fn`, `routes`, …),
  component sections and statements, view tags, component uses, attributes,
  event handlers (`press=`, `change=`, …), strings, templates with `${…}`,
  hex colours, numbers, comments and authored test steps.
- Bracket matching and auto-closing, `//` comment toggling.
- Indentation after lines that open a block (`component`, `if`, `view`, …).
- An outline (`cmd/ctrl-shift-o`) of declarations, actions, tasks and tests.

## Install (dev extension)

1. In Zed, open the command palette and run **zed: install dev extension**.
2. Pick this folder (`zed-exact-contract`).

Zed clones the grammar from
[GitHub](https://github.com/JulienNoel/contract-extension-zed) and compiles it,
so `rev` in `extension.toml` must name a pushed commit that contains
`tree-sitter-exact-contract/`.

## Layout

```
extension.toml                     manifest; points Zed at the grammar
languages/exact-contract/          Zed language config and tree-sitter queries
tree-sitter-exact-contract/        the tree-sitter grammar
  grammar.js                       source
  src/parser.c                     generated by `tree-sitter generate`
  examples/sample.contract         covers the main constructs
```

## Changing the grammar

```bash
cd tree-sitter-exact-contract
npx tree-sitter-cli@0.25.10 generate --abi 14
npx tree-sitter-cli@0.25.10 parse examples/sample.contract
```

Then commit and push, put the new commit hash in `extension.toml` (`rev`), and run
**zed: rebuild dev extension** (or reinstall it).

## How it works

Contract makes blocks by indentation and reserves almost no keywords, so the
grammar stays shallow: a file is a run of lines, and a line is a run of items
(names, literals, calls, `name=` attributes, `name:` fields, bracket groups).
`highlights.scm` then classifies each word by its position — the first word of a
line, the word after a declaration keyword, an attribute name, a callee —
following the VS Code grammar in Exact's `editors/vscode`. The grammar never
fails on real code: it parses 883 of the 885 `.contract` files in the Exact
repository with no error. The two it doesn't are a test fixture with a raw
carriage return inside a string, and a `#if` template that isn't Contract.
